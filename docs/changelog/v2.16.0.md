# v2.16.0 — 2026-09-07

**Type:** feat
**Scope:** web + harness + schema

Adds **Today** (`/today`), a new landing screen that lists signals — items TARS inferred
across email, meeting transcripts, calendar, and projects that appear to need a decision —
each with named actions, snooze, dismiss, and undo. It does not replace `/chat`; it sits above
it in the nav and is what the app opens to.

**Why:** the daily digest was a prompt-cron job that wrote prose into a chat conversation. It
told you what needed attention and then made you go do all of it by hand, in other screens.
Everything actionable it produced died as text. Today makes those items first-class objects
you can act on where you read them.

Design decisions worth recording:

- **A Signal is not a Task.** A Task is work you have committed to; a Signal is a claim that
  you might need to. Acting on a signal usually *produces* a To-Do and then the signal is
  done — it's a short-lived triage object, not a record to keep.
- **Signal work lands in To-Dos, not Projects.** A signal is a "don't forget this" prompt,
  which is what To-Dos are for. Projects is for tracked work with a status pipeline, and most
  signals never warrant a kanban card. "Add to Projects" stays available as an escalation
  chip. Time-pressured signals pass their urgency through as a due date.
- **Action dispatch splits in two.** `create_reminder` / `create_task` / `create_event`
  execute server-side, because their outcome is fully specified by the payload and there is
  nothing to negotiate. Everything needing composition or judgement (`draft_reply`,
  `move_event`, `open_meeting`, `save_brain`) opens a pre-seeded conversation instead. That
  keeps email behind the draft-card gate that already exists in chat rather than building a
  second, weaker gate on this screen.
- **Undo does not roll back side effects.** If acting created a To-Do, undo restores the
  signal and leaves the To-Do. Silently deleting something the user may have already edited is
  worse than leaving a visible row they can remove.
- **The list is never truncated.** A heavy morning should look heavy; hiding items behind
  "show 3 more" is backwards on a surface whose entire job is "what needs you". Structure
  comes from urgency grouping instead.
- **Three blank states, not one.** *earned* (you cleared it — shows a session receipt),
  *parked* (everything snoozed, nothing done), *quiet* (nothing came in). Treating all three
  as "ALL CLEAR" makes the screen lie two-thirds of the time, and a readout that lies is worse
  than no readout.
- **The headline is a verdict, not a tally.** "2 can't wait" / "Nothing urgent" rather than a
  raw count, which would make you do the triage maths yourself every morning.
- **The ambient backdrop carries state.** Confined to `/today`. Moss glow tracks a sun arc
  across the day, intensity scales with open signal count, ALL CLEAR collapses it to the
  existing boot glow. Decoration would have broken the "accent as signal" rule; encoding state
  earns it.
- **`.ics` is served from a real endpoint, never a client blob.** Blob URLs and
  location-navigation downloads both break inside the installed PWA shell — that was the
  v2.15.1 → v2.15.5 Second Brain export saga.

Also fixed: `next.config.ts` now sets `allowedDevOrigins`. Next 16 blocks `/_next/*` dev
resources cross-origin and treats `127.0.0.1` and `localhost` as different origins, so
browsing the dev server on the wrong one left React unhydrated and the entire app
non-interactive, silently and on every page.

**Known gap:** signal *generation* from real sources is not built yet. `/today` will show
"NOTHING IN" in production until that job lands. `apps/harness/scripts/seed_signals.py` seeds
realistic rows for development.

**Migration:** `r5s6t7u8v9w0` — creates `signals`, with a `(user_id, dedupe_key)` unique
constraint so a dismissed signal doesn't return on the next sweep.
