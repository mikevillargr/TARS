# v2.17.1 — 2026-09-07

**Type:** fix
**Scope:** harness

`detect_calendar_conflicts` passed `time_min` / `time_max` to the Google Calendar client as ISO
strings. `GoogleCalendarClient.list_events` takes `datetime` objects and calls `.isoformat()` on
them itself, so every sweep raised `'str' object has no attribute 'isoformat'`, logged a warning,
and produced zero calendar signals.

**Why it escaped local testing:** no Google Calendar is connected in the local dev environment,
so the detector hit its "connector not configured" early return and never reached the call. The
first production sweep, where the calendar *is* connected, exposed it within two minutes.

That is the useful lesson here, not the typo: a detector that returns early on missing
configuration will report success locally no matter how wrong the code past that point is. The
fix is now covered by a test that stubs the connector and asserts it receives `datetime`
objects rather than strings, which would have caught this without a live calendar.

**Files changed:** `apps/harness/jobs/signal_generator.py`.
